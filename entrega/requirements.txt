# ─────────────────────────────────────────────────────────────────────────────
# POR QUÉ LA LISTA ES CORTA, Y POR QUÉ ESO ES DELIBERADO
#
# §1.4 define `generador.py` como un «Script Python que utilice el índice, lea
# el archivo de consultas y genere el archivo de resultados». Utiliza el índice
# ya construido; no reconstruye el corpus. Toda la extracción, el OCR, la
# normalización, la fragmentación y la codificación ocurrieron aguas arriba y su
# resultado está contenido en `base_vectorial/`.
#
# En consecuencia, aquí NO se requieren `pdfplumber`, `PyMuPDF`, `pytesseract`,
# `openpyxl` ni `mapbox-vector-tile`, ni el binario de Tesseract. Declararlos
# ampliaría la superficie de fallo de la instalación sin ninguna contrapartida, y
# una instalación fallida impide ejecutar el generador — que es exactamente lo
# que §1.4 castiga con la exclusión.
#
# Los cuatro primeros paquetes son los únicos imports de terceros de toda la
# cadena que `generador.py` recorre. Verificado leyendo los imports de
# `generador.py`, `lib/retrieval/{consultas,search,fragmentos,grafo}.py`,
# `lib/embedding/encoder.py`, `lib/chunking/chunker.py`, `lib/graph/canonical.py`
# y `lib/core/chunk.py`: los tres últimos no importan nada de terceros. Los cinco
# siguientes son transitivas que se fijan porque determinan los valores numéricos
# de los embeddings: fijarlas es lo que hace que el ranking sea el mismo y no
# solo «parecido», que es lo que §1.4 exige.
#
# La lista completa que se usó para CONSTRUIR el índice está en el
# `requirements.txt` de la raíz del repositorio, y no hace falta aquí.
#
# ─────────────────────────────────────────────────────────────────────────────
# EL MODELO SE DESCARGA EN TIEMPO DE EJECUCIÓN
#
# `sentence-transformers` descarga `BAAI/bge-m3` (4,35 GB) desde HuggingFace la
# primera vez. La revisión está fijada por sha de commit en
# `lib/embedding/encoder.py`:
#
#     5617a9f61b028005a4858fdac845db406aefb181
#
# Sin fijarla podría descargarse otra versión del modelo, los vectores de la
# consulta dejarían de residir en el mismo espacio que los del índice y el
# ranking cambiaría sin emitir ningún error.
#
# Codificar las 50 consultas lleva unos 8 minutos en CPU y segundos en GPU.
#
# Se declara `faiss-cpu` y NUNCA `faiss-gpu`: esto se ejecuta en la máquina de
# quien evalúa, donde puede no haber GPU, y un índice plano (`IndexFlatIP`) no
# requiere entrenamiento, así que la GPU no aportaría nada.
#
# ⚠️ NO añadir `pathlib`: el paquete `pathlib` de PyPI es un backport antiguo que
# puede sombrear el `pathlib` de la librería estándar. Estuvo aquí por error.
#
# ─────────────────────────────────────────────────────────────────────────────
# LO QUE ADEMÁS DE ESTOS PAQUETES HACE FALTA PARA REPRODUCIR
#
# La reproducción no depende solo de pip. Dentro de `base_vectorial/grafo/` tiene
# que estar `chunk_index.json` junto a `grafo.graphml`: es el mapa
# `chunk_id → faiss_id` que usa la integración del grafo de §8.5. Sin él el grafo
# no puede aportar ningún fragmento, `generador.py` lo avisa por pantalla y
# desactiva §8.5 en lugar de fingir que se aplica — pero la salida ya no
# coincidiría con la entregada.
#
# ─────────────────────────────────────────────────────────────────────────────
# ENTORNO DE REFERENCIA OBSERVADO
#

# sha256 3617145844f10f81b3b3bb3214d1e240691c3d954b71fc415ba1298dd3fb44ef)

# Los pines de abajo son exactamente esas versiones, de modo que instalar este

#
# Sobre la independencia del entorno: la configuración ANTERIOR a la integración
# del grafo se verificó idéntica byte a byte en dos sesiones independientes, con
# descarga fresca del modelo y versiones distintas de biblioteca
# (`sentence-transformers` 5.6.0 y 5.7.0, `numpy` 2.0.2 y 2.5.1). Esa evidencia
# es de aquella configuración, no de esta: la salida actual está verificada por
